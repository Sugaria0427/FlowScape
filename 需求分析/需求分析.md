# FlowScape 需求分析

FlowScape 是面向异构算力场景的可视化决策实验平台，支持调度仿真、策略对照和运行状态观测。项目定位见 [README](../README.md)，各主题负责人和调研入口见 [分工.md](分工.md)。

## 需求说明

### 目标用户与使用场景

- **实验者**选择已配置的集群和调度策略，载入预设负载，运行仿真并查看作业状态、排队原因和执行结果。从选定场景到查到指定作业的结果是一条完整流程。
- **场景设计者**手工配置一小批作业，例如两项争用同一张 GPU 的作业，验证某个调度现象。负载有效时可用相同的仿真流程运行，配置错误时可定位到具体作业和字段。实验者也可以承担这一角色。

预设入口适合重复运行已有场景，用户应能在启动前核对已载入的作业。手工入口适合构造小规模可手算的用例，用户可填写或导入自行编制的作业清单。两条路径共用校验、启动和结果查询行为。作业配置至少能确定作业标识（可自动分配）、相对仿真起点的到达时刻、资源请求，以及模拟运行时长或足以确定时长的负载描述。卡型约束随具体作业需要填写。

### 作业状态与等待原因

| 状态变化 | 触发条件 | 用户可观察的结果 |
| --- | --- | --- |
| 未到达 → 排队 | 仿真时钟达到作业到达时刻 | 作业进入待调度队列。正在等待调度时可查询当前原因。 |
| 排队 → 运行 | 调度策略选中作业并成功分配请求的资源 | 记录开始时刻和分配结果，清除当前等待原因。 |
| 运行 → 完成 | 作业完成模拟执行 | 记录结束时刻并释放资源。可按作业标识查询结果及历史状态。 |

「未到达」用于表示已载入负载、尚未到达仿真提交时刻的作业。到达与开始可以发生在同一仿真时刻。观察窗口结束时，排队或运行中的作业应保留当时的状态，并标记为该窗口内未完成。校验失败属于输入处理结果。取消、故障和限时结束的状态转换随对应功能评审。

排队作业按调度结果显示原因。请求因资源已被占用而无法分配时显示「暂缺资源」。请求因所需节点暂时离线或不可调度而无法分配时显示「所需节点暂不可用」。策略明确优先满足其他更高优先级作业时显示「等待优先级」。原因尚未确定时显示「待调度」。记录原因及其对应的仿真时刻，重新调度后更新当前原因。
