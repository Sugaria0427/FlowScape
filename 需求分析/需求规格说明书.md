本说明书把各主题的调研结论和候选需求整合为一份可评审的规格。需求编号沿用工作稿，规则细节、手算样例和调研出处以工作稿为准，本文给出统一口径、首版范围、追踪关系和待决问题。

## 1 引言

### 1.1 目的

明确 FlowScape 首版要做什么、不做什么、怎样算做完，作为概要设计、测试设计和团队评审的共同输入。

### 1.2 产品范围

FlowScape 是面向异构 GPU 集群的调度仿真与策略对照平台。用户配置集群和作业负载，在离散事件仿真中运行调度策略，观察同一仿真时刻的队列、资源和等待原因，在相同输入下比较不同策略，并凭实验清单复现结果。

核心价值有三项：

1. **同任务流、同时钟对照**：不同策略使用相同的负载、集群和随机输入，在同一仿真时刻比较。
2. **等待可解释**：区分作业因资源被占用、所需节点不可用还是调度顺序而等待。
3. **结果可复现**：实验输入冻结为带哈希的清单，重跑结果零偏差。

### 1.3 术语

| 术语 | 含义 |
| --- | --- |
| 仿真时刻 `sim_time` | 相对仿真起点的秒数，与墙钟无关。 |
| 事件序号 `event_seq` | 同一运行内事件的全局处理次序，用于区分同一时刻的多个事件。 |
| 实验 / 运行 | 一个实验（`experiment_id`）固定一份输入，可包含多个策略的运行（`run_id`），每个运行独立演化。 |
| 尝试 `attempt_id` | 作业的一次实际运行区间。首版非抢占，每个作业至多一次尝试；历史轨迹可有多次。 |
| 卡位 / 卡组 | 卡位为 `(node_id, gpu_id)`；卡组为一次分配给作业的全部卡位。 |
| 静态不可满足 | 在场景配置及已定义的资源变化下，任何时刻都不存在可行卡组，启动前拒绝。 |
| 暂时不可分配 | 场景内存在可行卡组，但当前被占用或所在节点离线，作业留在队列。 |
| 观察窗口 `[a, b)` | 统计用的左闭右开时间区间，单位秒。 |
| 水位 | 某个运行已处理完的最大仿真时刻。 |
| 分配占用率 | 窗口内已分配的卡秒除以配置卡数与窗口长度之积，不代表 GPU 实际忙碌程度。 |
| 实际利用率 | 来自 GPU 传感器采样的忙碌百分比，与分配占用率分列。 |
| 调度可见请求 / 真值执行画像 | 前者是策略可读的到达时刻、资源请求和估计时长；后者是仿真器用于推进的实际时长，策略不可读。 |
| 实验清单 `ExperimentManifest` | 冻结一次实验全部输入及其 SHA-256 哈希的不可变文件。 |

## 2 总体描述

### 2.1 用户角色

| 角色 | 目标 | 典型操作 |
| --- | --- | --- |
| 实验者 | 用已有场景比较策略、解释结果 | 选择集群、策略和预设负载，运行，查看状态、原因和指标，导出与重跑 |
| 场景设计者 | 构造小规模可手算用例，验证某个调度现象 | 填写或导入作业清单，定位配置错误，运行并核对结果 |

两种角色可由同一人承担。预设和手工两条入口共用字段语义、校验、启动和结果查询行为。

### 2.3 设计与实现约束

以下约束来自需求本身，任何实现方案都必须满足：

1. **确定性**：相同清单的运行结果逐事件一致；同一时刻的处理顺序由引擎统一定义并记录 `event_seq`；平级按 `arrival_time`、`input_seq`、`job_id` 稳定排序。
2. **无未来信息**：策略只能读取调度可见请求，不得读取实际时长。
3. **统一单位**：内部和导出使用秒与 GPU·秒，展示层换算分钟时须标注单位。
4. **账本守恒**：任一时刻分配卡数不超过物理容量，分配与释放一一对应。
5. **数据不伪造**：缺失值不补零，未完成作业不混入完成均值，推断值与事实分别标识。

### 2.4 假设与依赖

- 首版只模拟 GPU 批作业，作业时长事先确定且等于调度可见估计时长。
- 首版不依赖外部真实集群或调度器，所有行为在仿真内产生。
- 运行环境、部署形态和规模目标尚未在需求中给出，见 9.2。

## 3 首版范围

### 3.1 首版主流程

1. 从预设或手工清单载入集群与负载。
2. 字段校验与静态可行性校验，失败时整批拒绝并给出字段级反馈。
3. 选择稳定 FIFO 和可行即运行两种策略，生成实验清单并启动。
4. 在同一仿真时刻查看队列、等待原因、节点卡位占用和单作业事件。
5. 按共同半开窗口查看两种策略的指标对照。
6. 导出结果，凭清单重跑并核对一致。

RES-A 用于核对资源匹配和等待原因，SCH-A 与 EXP-A 用于核对策略对照、指标和复现。这些手算样例同时作为预设场景和回归测试基准。

### 3.2 范围边界

| 阶段 | 内容 |
| --- | --- |
| P0 首版 | FR-JOB-01～05、FR-RES-01～02、FR-SCH-01、FR-SCH-05、FR-SCH-07（可行即运行）、FR-OBS-01、FR-OBS-03（仅分配占用率）、FR-OBS-04、FR-EXP-01～04、结果导出；NFR-SCH-01～03、NFR-EXP-01～02 |
| P1 | 严格优先级 FIFO、队首保护回填、历史公平优先级、租户配额与借用、公开轨迹导入与清洗、多尝试回放、实际利用率曲线、逐卡显存过滤 |
| P2 | 抢占、层级配额、跨节点放置与拓扑、GPU 共享 |
| 首版不做 | 取消、故障、超时等结束状态；混合卡型的单作业请求；时长不确定的作业；对真实集群下发调度 |

## 4 功能需求

### 4.1 负载输入与校验（FR-JOB-01～03、FR-RES-01、FR-EXP-02）

**集群配置字段**

| 字段 | 规则 |
| --- | --- |
| `node_id` | 节点唯一标识。 |
| GPU 清单 | 每张卡有节点内唯一的 `gpu_id` 和非空 `model`；按型号给卡数的预设在载入时展开为稳定编号的卡位；同一节点可有多种型号。 |
| `initial_online` | 省略时为在线。 |
| 上下线事件 | 按仿真秒记录节点何时可接受新分配，随平台输入冻结。 |

**作业字段**

| 字段 | 可见性 | 规则 |
| --- | --- | --- |
| `job_id` | 调度可见 | 唯一，可自动分配。 |
| `input_seq` | 调度可见 | 输入顺序，用于稳定平级。 |
| `tenant_id` | 调度可见 | 租户标识；首版只用于统计。 |
| `arrival_time` | 调度可见 | 相对仿真起点的秒数，非负。 |
| `req_gpu` | 调度可见 | 正整数卡数。 |
| `gpu_spec` | 调度可见 | 省略为任一型号；填写时为一个型号或非空备选集合；多卡作业所有卡同型号、同节点。 |
| `gpu_milli` | 调度可见 | 首版固定 1000（整卡）；其他取值在共享能力启用前拒绝。 |
| `est_duration` | 调度可见 | 调度可见的估计时长，秒。 |
| `actual_duration` | 仅仿真器 | 真值时长，秒；首版须等于 `est_duration`。 |

**校验规则**

1. 字段级：取值范围、重复的节点、卡位或作业标识、未知卡型、不支持的约束。
2. 静态可行性：对每项请求，检查其到达时刻或之后，场景配置中是否存在过同节点、同型号、空闲数量足够的完整卡组，忽略作业占用和队列顺序。已定义的恢复事件可以让离线节点通过检查。
3. 失败反馈指出作业、字段、请求数量和最大可匹配卡数。
4. 任一作业失败则整批拒绝，没有作业进入队列。
5. 预设入口和手工入口使用同一套校验，结果一致（AC-JOB-07）。

### 4.2 作业生命周期与等待原因（FR-JOB-04～05）

| 状态变化 | 触发 | 可观察结果 |
| --- | --- | --- |
| 未到达 → 排队 | 仿真时钟到达 `arrival_time` | 进入待调度队列，可查询当前原因 |
| 排队 → 运行 | 策略选中且原子分配成功 | 记录开始时刻和卡组，清除当前原因 |
| 运行 → 完成 | 模拟执行结束 | 记录结束时刻并释放卡组 |

到达与开始可以发生在同一时刻。观察窗口结束时，排队或运行中的作业保留当时状态，并标记为窗口内未完成。校验失败属于输入处理结果，不是作业状态。

| 等待原因 | 判定条件 |
| --- | --- |
| 暂缺资源 | 在线节点的同型号总容量能满足，但同节点空闲卡数不足。 |
| 所需节点暂不可用 | 静态校验已通过，但当前没有在线节点能提供完整卡组。 |
| 等待优先级 | 策略明确优先满足排在前面的其他作业。 |
| 待调度 | 已到达但尚未经过调度尝试。 |

每次调度尝试后更新当前原因并记录对应的仿真时刻和依据，历史原因保留用于回放。

### 4.3 资源匹配与分配（FR-RES-02）

1. 运行时先检查在线节点的同型号总容量，再检查同节点空闲卡数，分别对应「所需节点暂不可用」和「暂缺资源」。
2. 匹配器向策略提供可行卡组；放置规则固定为按 `node_id`、`model`、`gpu_id` 的标识顺序取第一组，策略对照时不变。
3. 分配是原子的：一次占用全部请求卡位，或保持原状。
4. 记录作业、节点、型号、卡位和仿真时刻，完成后释放同一卡组。

### 4.4 调度（FR-SCH-01、FR-SCH-05、FR-SCH-07）

**同一时刻的处理顺序**：①处理完成并释放资源 → ②处理节点上下线 → ③处理到达 → ④反复调度直到无状态变化（固定点）→ ⑤发布该时刻快照。调度在到达、完成和资源变化时触发。

| 首版策略 | 排序 | 队首暂时不适配时 | 可观察输出 |
| --- | --- | --- | --- |
| 稳定 FIFO | `arrival_time`、`input_seq`、`job_id` | 阻塞，不越过队首 | 队列顺序、匹配失败原因、开始和结束事件 |
| 可行即运行 | 同上 | 跳过当前不适配项，继续检查后续作业 | 每项跳过或准入的原因、越过次数、等待时长；不承诺无饥饿 |

每轮调度记录决策：候选次序、每个候选的匹配结果、放置结果和原因、分配与释放。P1 引入配额后，配额准入与物理放置分层记录。

### 4.5 状态观测与策略对照（FR-OBS-01、FR-OBS-03、FR-OBS-04）

| 视图 | 回答的问题 | 首版内容 |
| --- | --- | --- |
| 当前队列 | 哪些作业到了、在等什么、等了多久、哪些在运行 | 作业、租户、到达时刻、状态及起始时刻、当前原因及其时刻、请求、当前分配；按状态和租户筛选，按到达或等待时长排序 |
| 单作业历史 | 作业何时运行、在哪些卡上、原因怎样变化 | 状态区间、卡位、原因历史、事件序号；支持暂停、拖动和逐事件跳转 |
| 集群资源 | 哪些卡已分配、哪些空闲或离线 | 按节点和型号展开的卡位占用、可用性事件；分配占用率附单位、窗口和容量 |
| 策略对照 | 换策略后同一时刻谁先运行、拥塞如何变化 | 同步游标下的各策略队列、时间线和指标，附共同输入哈希 |

**同时钟语义**：用户定位到时刻 t 时，每个运行处理完全部 `sim_time ≤ t` 的事件及该时刻触发的调度后发布快照。水位未达 t 的运行显示「尚未计算到该时刻」，不得用旧快照冒充。播放速度只影响墙钟节奏，不影响结果。不得按各自第 N 个事件或完成百分比对齐。

首版只有仿真数据源，没有传感器数据，实际利用率显示为无数据，不以分配占用率代替。

### 4.6 实验、指标与导出（FR-EXP-01～04）

**实验清单**冻结 `platform_config`、`workload_input`（调度可见请求与真值执行画像分开保存）、外生事件、`policy_spec`（策略标识、版本、参数）、`random_seed`、`sim_window` 与 `engine_version`，每项附 SHA-256 哈希。凭导出的清单及其引用的输入文件即可重跑。缺少关键配置或哈希校验失败时，在启动前拒绝重跑。

**同源校验**：多策略对照时，除 `policy_spec` 外各项哈希必须一致，否则禁止直接归因并列出差异字段。

**逐作业指标**（仅对时间戳已知者计算）

| 指标 | 定义 |
| --- | --- |
| 首次等待 | `first_start_time - arrival_time` |
| 执行时长 | `finish_time - first_start_time` |
| 周转时间 | `finish_time - arrival_time`，仅已完成作业 |
| 膨胀率 | `turnaround_time / execution_time`，仅 `execution_time > 0` 的已完成作业 |

**窗口 `[a, b)` 汇总**

| 指标 | 定义 |
| --- | --- |
| 完成数 | `a ≤ finish_time < b` 的作业数；`finish_time == b` 的作业在 t=b 快照中显示已完成，但计入下一窗口 |
| 未完成数 | `arrival_time < b` 且未在 b 前完成的作业，按处理完 `sim_time < b` 事件后的状态细分为运行中和排队中，已运行或已等待的下界计算至 b |
| 吞吐 | 完成数 / `(b - a)`，作业/秒 |
| 分配 GPU·秒 | 各分配区间与窗口交集长度 × 卡数之和 |
| 分配占用率 | 分配 GPU·秒 / (配置卡数 × `(b - a)`)；按在线容量计算须另命名 |
| 租户 Jain 指数 | `(Σx)² / (n·Σx²)`，x 为各租户窗口分配 GPU·秒，分母为 0 记 NA；仅在同卡型、同权重前提下直接解释 |

**导出**：逐作业 CSV 和窗口汇总 JSON，均带清单哈希和单位声明。

## 5 数据需求

| 数据 | 方向 | 内容 | 阶段 |
| --- | --- | --- | --- |
| 平台配置 | 输入 | 节点、卡位、型号、初始在线状态、上下线事件 | P0 |
| 工作负载 | 输入 | 调度可见请求；单独保存的真值执行画像 | P0 |
| 策略配置 | 输入 | 策略标识、版本、参数 | P0 |
| 实验清单 | 输入 / 输出 | 上述输入、种子、窗口、引擎版本及各项哈希 | P0 |
| 事件记录 | 输出 | 每个运行按 `event_seq` 记录到达、开始、完成、原因变化、节点状态、调度决策 | P0 |
| 逐作业结果 | 输出 | 起止时刻、分配卡组、终态、各项指标 | P0 |
| 窗口汇总 | 输出 | 4.6 中的汇总指标及完成数、未完成数 | P0 |
| 公开轨迹 | 输入 | Philly Traces、Alibaba GPU v2023/v2020 | P1 |

公开轨迹的字段映射与限制见工作稿「仿真数据源」DS-OBS-01、DS-EXP-01、DS-EXP-02，要点如下：

- Philly 有分配尝试的事实，但没有请求量和排队原因，适合回放。
- Alibaba v2023 适合异构卡型约束和整卡筛选；只有 `Succeeded` 记录可直接给出自然完成时长。
- Alibaba v2020 适合多租户画像，以及请求量与实测利用率对比；`start_time == 0` 是缺失占位。
