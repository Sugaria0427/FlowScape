# FlowScape 需求分析分工

## 共同交付

每人把调研结论直接填入 [需求分析.md](需求分析.md)。先记录参考项目解决的用户问题、具体行为和适用条件，再说明 FlowScape 哪些场景有同样的问题、哪些能力适合借鉴、需要做什么调整。优先找项目公开的需求、设计提案或用例。依据来自功能手册时，标明哪些是文档描述的行为，哪些是据此推导的需求。

每项候选需求填上来源、负责人、建议优先级和验收场景。验收场景写清输入、操作和可观察的预期结果。存在分歧时，把备选方案和选择依据填入「待确认问题」。

使用公开运行轨迹时，把数据版本、采集场景、字段含义、缺失情况和适用范围填入「仿真数据源」。说明哪些字段可直接使用、哪些可由原始记录推算、哪些需要构造仿真输入。

## 黄帅｜用户角色与作业流程

主研 **Slurm**。从提交者和实验者的视角走查提交作业、等待调度、运行、结束和查询结果。核对提交时哪些信息必填，作业有哪些状态，以及等待原因如何区分资源不足、优先级较低和所需节点不可用。比较 FlowScape 用户手工配置一批作业和载入预设负载两条流程。阅读 [Slurm 概览](https://slurm.schedmd.com/overview.html)、[sbatch](https://slurm.schedmd.com/sbatch.html)、[作业状态](https://slurm.schedmd.com/job_state_codes.html)和[作业等待原因](https://slurm.schedmd.com/job_reason_codes.html)。

**交付**填写目标用户、主要用例和作业状态转换，给出一次完整仿真、暂时无可用资源、非法作业请求的候选行为与验收场景。与杜志鸣对齐用户可见的状态名称和等待原因，汇总五人的建议形成首版范围供团队评审。

## 孙珂豪｜异构资源与作业约束

主研 **Slurm GRES** 和 **Kueue ResourceFlavor**。对照两者如何区分 GPU 型号、记录节点资源、表达作业所需的类型和数量。分析多卡作业是否要求同节点，混合卡型能否满足请求，以及如何区别「所需资源存在但正被占用」和「集群配置本身无法满足」。评估显存、拓扑和共享需求各自的用途及所需数据。阅读 [Slurm GRES](https://slurm.schedmd.com/gres.html)和 [Kueue ResourceFlavor](https://kueue.sigs.k8s.io/docs/concepts/resource_flavor/)。

**交付**填写集群配置与作业请求的候选字段、字段含义和匹配规则。给出一组双型号 GPU 的最小配置，覆盖型号匹配、数量不足和跨节点分配边界，交给马浩博作为策略分析的输入。

## 马浩博｜调度策略、公平性与配额

主研 **Slurm 调度与多因子优先级**、**Kueue ClusterQueue 和 Cohort**。分析先来先服务、回填、等待时长和历史用量如何影响调度；区分能否分配资源、作业排序、队列配额、配额借用与抢占各自解决的问题。用同一份拥塞任务流推演不同规则的行为，记录吞吐、长作业等待和租户公平性之间的取舍。阅读 [Slurm 调度配置](https://slurm.schedmd.com/sched_config.html)、[Slurm 多因子优先级](https://slurm.schedmd.com/priority_multifactor.html)、[Kueue ClusterQueue](https://kueue.sigs.k8s.io/docs/concepts/cluster_queue/)和 [Kueue Cohort](https://kueue.sigs.k8s.io/docs/concepts/cohort/)。

**交付**填写候选策略对照表，包括触发条件、排序依据、同优先级处理和可观察的行为。给出队首作业暂时缺资源、两个租户争用 GPU 时的预期调度顺序或资源分配，并把可手算的例子交给龚旭。

## 杜志鸣｜状态观测、回放与策略比较

主研 **Slurm squeue、sacct** 和 **Grafana State timeline**。分析用户在当前队列、单个作业历史、集群占用和策略对照四个视图中分别要回答什么问题，并列出各视图所需的数据。阅读 [squeue](https://slurm.schedmd.com/squeue.html)、[sacct](https://slurm.schedmd.com/sacct.html)和 [Grafana State timeline](https://grafana.com/docs/grafana/latest/panels-visualizations/visualizations/state-timeline/)。

调研 **Microsoft Philly Traces**。用 `cluster_job_log` 的提交时间、每次调度尝试的起止时间和分配的 GPU，推演一条包含多次尝试的作业回放。核对 `cluster_gpu_util` 的分钟级利用率能支持哪些视图，说明缺少结束时间或排队原因时如何显示。阅读 [Microsoft Philly Traces 字段说明](https://github.com/msr-fiddle/philly-traces#trace-details)。

**交付**填写「用户问题 → 视图 → 字段」对照表，给出一条可回放样例和带缺失记录的验收场景。说明策略对照如何对齐同一仿真时刻。与黄帅核对状态语义，与龚旭核对指标单位和观察窗口。

## 龚旭｜实验输入、指标与复现

主研 **Batsim** 的平台、负载和逐作业结果格式。分析重跑实验要保存哪些输入、对比策略时要固定哪些条件。定义等待时间、周转时间和 GPU 利用率的单位、观察窗口及未完成作业的统计方式。阅读 [Batsim 平台](https://batsim.readthedocs.io/en/latest/input-platform.html)、[Batsim 工作负载](https://batsim.readthedocs.io/en/latest/input-workload.html)和 [Batsim 作业结果](https://batsim.readthedocs.io/en/latest/output-jobs.html)。

调研 **Alibaba Cluster Trace GPU v2023 与 v2020**。从 v2023 的节点和 Pod 数据提取 GPU 型号、卡数、共享份额及到达时间，检查历史调度和删除时间在什么条件下可用于估算运行时长。从 v2020 的任务资源请求和传感器表核对 GPU 请求量与实际利用率的统计口径。比较两套生产集群数据用于构造目标场景时的适用范围。阅读 [Alibaba GPU v2023 字段说明](https://github.com/alibaba/clusterdata/tree/master/cluster-trace-gpu-v2023)和 [Alibaba GPU v2020 字段说明](https://github.com/alibaba/clusterdata/tree/master/cluster-trace-gpu-v2020)。

**交付**填写数据字段到仿真输入的映射，注明数据版本、采样范围、转换规则和缺失值处理。给出一份可复现的小规模负载样例、指标口径和验收场景，覆盖固定输入重跑、同一任务流对比两种策略、结束时仍有作业未完成。用马浩博提供的小例子核对可手算指标。
